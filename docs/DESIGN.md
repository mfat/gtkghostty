# Design

gtkghostty is a GTK 4 widget written in C on the stable **libghostty-vt 1.0** C ABI,
introspectable through GObject Introspection (`GtkGhostty-1`). This page records the rules the
code follows and the platform facts behind them. Credits for ported and studied code are in
[`NOTICE`](../NOTICE).

## Why this design

Ghostty's own GTK widget (`GhosttySurface`) cannot be reused: it is internal to the Ghostty
application, tied to its global state and to a Linux-only DMA-BUF renderer. libghostty-vt is
Ghostty's terminal core published as a library with a versioned, stable ABI: parser, screens,
scrollback, render state, key/mouse/focus/paste encoders, selection, search and a text formatter.
gtkghostty adds only the GTK side: drawing, input routing, scrolling and an optional process
adapter.

## Structure

| File | Role |
|---|---|
| `src/gtk-ghostty-terminal.c` | `GtkGhosttyTerminal`: feeds bytes to libghostty-vt, draws its render state with `GtkSnapshot` and Pango, turns GTK input into terminal input |
| `src/gtk-ghostty-pty.c` | `GtkGhosttyPty`: optional; runs a program on a POSIX PTY or Windows ConPTY and `attach()`es it to a terminal |
| `src/gtk-ghostty-tables.c` | Generated by `tools/gen_tables.py`: GDK key names → `GhosttyKey`, box-drawing glyph table |
| `tests/` | Python/GI tests (`tests/run.sh`); `test_keyboard.py` drives real key events with xdotool |
| `stubs/` | Python type stubs, generated by `tools/gen_stubs.py`; `tests/test_stubs.py` keeps them current |
| `packaging/windows/` | libghostty-vt build (all platforms) and the gvsbuild Windows zip |

## Rules

1. **The widget never owns a process.** Output goes in with `feed()`; what the user does comes
   out as `input`, the terminal's answers to queries as `reply`, the grid size as `size-changed`.
   Any transport fits: a PTY (`GtkGhosttyPty`), SSH, a serial port, a socket.
2. **No protocol code.** If libghostty-vt has an API for it, call it. The exceptions are regex
   and case-sensitive search (libghostty's search is literal and ASCII-caseless; it is used for
   plain searches) and plain-text URL detection (left to the embedder through `get_line_at()`).
3. **Keys go through the input method first.** A composition (dead keys, CJK) is sent as text; a
   character the input method only passes through is encoded by libghostty's key encoder, so
   programs that ask for the kitty keyboard protocol get it, with releases and repeats. Whether a
   commit was a composition is decided by comparing it with what the key types alone: not every
   input method shows a preedit while composing.
4. **Nothing is injected into a partly received sequence.** Changes that need a VT sequence (the
   default cursor style) wait until the parser is at ground
   (`ghostty_terminal_vt_write_until` with `GHOSTTY_TERMINAL_BOUNDARY_GROUND`).
5. **Rows are laid out once.** Pango layouts are cached per row and rebuilt only for dirty rows;
   each run of cells gets letter spacing so glyphs land exactly on the grid, wide cells are
   scaled to two cells, and box drawing, block elements, Powerline, braille and sextants are drawn
   as shapes, not taken from the font.
6. **Default colours are always set**, starting from the renderer's own, so colour queries
   (OSC 10/11, used by editors to pick a light or dark look) are always answered.

## Platform facts (verified)

- **ConPTY** forwards a program's kitty keyboard request but turns kitty-encoded keys into text,
  and repaints its own screen after a resize. Embedders on ConPTY set `legacy-keyboard` and turn
  off `pull-history-on-grow`; `GtkGhosttyPty.attach()` does both on Windows. OSC 8 links survive
  ConPTY.
- **Pango on Windows** falls back to other fonts only along its built-in alias lists, so a
  named family such as Consolas shows no Korean, CJK or emoji. On Windows the widget appends
  Malgun Gothic, Microsoft YaHei, Yu Gothic, Segoe UI Emoji and Segoe UI Symbol to every font.
  Mixed-script relayout is also about four times slower there than ASCII, which is why the row
  cache matters.
- **libghostty-vt** prunes scrollback by whole pages, its byte limit defaults to about one page
  (set it, or history is tiny), and a full reset (RIS) clears history.
- **GTK's simple input method** commits plain characters itself; a key controller with an input
  method attached never sees them, which is why the widget filters keys itself.

## Security

Remote output is untrusted. The widget answers queries only through `reply`, makes titles valid
UTF-8 and draws no images yet.

- **Clipboard (OSC 52):** programs may *set* the clipboard or the primary selection (plain text),
  as tmux and editors do to copy over SSH; `allow-clipboard-write` turns that off. They can never
  *read* it: no read handler is registered, so a remote host cannot see what the user copied
  locally. (libghostty-vt needs a read answered synchronously, and GTK reads the system
  clipboard asynchronously.)
- **Paste** is sanitised, and bracketed when the program asks. Whether to confirm an unsafe paste
  (`paste_is_safe()`) is the embedder's decision, as is what to do with links.

## Not done yet

- Accessibility (`GtkAccessibleText`): logical lines with soft wraps joined, and row identities to
  tell scrolling from new output. Kwi's `TerminalAccessible` is the design reference.
- Kitty graphics, with file, temporary-file and shared-memory media off by default (over SSH
  they would let a remote program read local files).
- Search selects one hit and does not highlight all of them.
- `encoding` covers ASCII-compatible legacy encodings (Latin-1, Shift_JIS, GBK and the like)
  by converting at the edges; libghostty-vt itself only reads UTF-8, so UTF-16 is out.
- Windows on real hardware with a GPU (tested so far on VMs, which use GTK's Cairo renderer).
